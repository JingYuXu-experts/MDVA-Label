# 2026-11-16 AR训练数值异常与接续

## 故障事实

北京时间01:32:32，AR-A1-s2026在第28轮因“训练损失非有限值”退出，01:32:37队列按保护规则停止后续实验。不是日志中此前的WinError 5，也没有显存不足证据。

原运行保留在`out/training-20261112-v2/revisions/io-fast-v1/runs/AR-A1-s2026`。第27轮检查点完整，最佳第26轮验证Dice为77.0505%。模型、Adam、调度器、GradScaler、随机状态及27轮历史齐全，模型和优化器张量均有限。

在独立副本重放第28轮，第1297个micro-batch（从1计）复现。两张输入来自2012-01-22和2012-06-07的HMI磁图。输入与权重有限，首个异常层为`decoders.1.layers.0`，FP16中间特征超出可表示范围；同一时刻权重与同一输入在FP32下前向正常，BCE+Dice损失为0.10685726，反向梯度也有限。原始数据、掩膜及失败文件没有改写。

不能因此认定输入损坏、标签漏标或训练没有学习效果。它是已复现的精度范围问题。

## 独立修复版本

新增`io-ar-guard-v1`，不修改原数值代码及旧检查点身份：

- 适用范围仅AR-A1-s2026及尚未开始的AR-A0-s42、AR-A0-s2026，仍在原批准顺序内。已完成的种子不重训，CH/FL/预测不变。
- 保留无损输入缓存、512分辨率、micro-batch 2、有效batch 8、损失、优化器、采样和早停。
- 有限AMP输出原样返回；非有限前向仅重试一次FP32，FP32仍异常或输入/参数非有限则停止。没有裁切数值、跳过样本或把NaN当背景。
- 前向重放仅允许现有无随机层、无可变缓冲的U-Net；禁止将该方法直接用于Dropout或BatchNorm等有状态图。
- 记录每次重试与连续次数，连续128次以上停止排查持续数值不稳定。正常前向会清零连续计数，总次数仍保留；不因相隔很久的正常可恢复事件累计次数而反复中断。
- GPU互斥、显存及内存门槛继续生效。检查点仍按完整epoch提交，暂停/关机恢复机制不变。

PyTorch官方说明允许在不稳定计算区域关闭autocast并转为FP32；本修复以实测复现为依据，见[AMP说明](https://docs.pytorch.org/docs/2.10/amp.html)。
