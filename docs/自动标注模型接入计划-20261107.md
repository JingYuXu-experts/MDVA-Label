# MDVA 自动标注模型接入计划

> 2026-11-08 范围与方法更新：本项目聚焦太阳结构识别、对象整理和人工核查，不建设耀斑预测模型。下文原“首选模型”和训练安排是历史讨论，尚未经过 baseline 复现，不再作为实施定案；相关安装与下载已停止。当前研究方向与实验约束见 [识别与对象整理研究方案](太阳结构识别与对象整理研究方案-20261108.md)。不得以本文件的旧候选架构跳过文献核验和复现。

状态：选型与实施建议，尚未安装 PyTorch、下载权重、修改模型实现或开始训练。当前用户要求接入模型的方向替代历史交接中的“禁止深度模型”限制；原始数据只读、本地运行和人工审核边界继续保留。

## 一、结论

采用两条互补路径：SAM 2.1 Tiny 起步、Small 对照，用于点击/框选辅助分割；领域模型负责无提示的批量自动分割。CH、FL 优先 U-Net + ResNet18，ResNet34 作为容量对照；AR 优先验证 torchvision Mask R-CNN ResNet50-FPN，U-Net 二值前景作为基础对照。三个类别使用与观测类型对应的模型，不把三种未配准观测直接堆叠成同一张多通道图。

首轮保留现有清晰度、坏像元、重复检查，不新增复杂模型。图像检测框可以从已有分割结果派生，无须首先再训练一个独立检测器。耀斑预测的数据实际位于同级目录，可以开展独立基线；实施顺序仍优先自动标注，但不再以“本地缺少预测数据”为后置理由。

## 二、来源与本地事实

来源论文是 [Solar Situation Awareness and Flare Forecasting Dataset for Operational Applications](https://www.nature.com/articles/s41597-026-08005-5)，相关原始团队介绍为[国家空间科学中心说明](https://cssar.cas.cn/xwdt2015/kydt2015/202609/t20260922_8286097.html)，给出的数据 DOI 是 `10.57760/sciencedb.space.03541`。论文说明中包含多源太阳观测、结构标注及未来 24 小时耀斑相关数据产品。本次无法从用户提供的 ScienceDB 文件预览页取得足够的文件版本和许可信息，因此实施前仍要核对该文件与 DOI 数据发布版本、说明文档及数据使用许可；论文开放许可不能代替数据许可。

**范围纠正：此前仅检查 `Situation Awareness Dataset`，漏查同级目录，并错误地将“该子目录没有预测表”解释为“本地数据缺少预测产品”。这一判断已撤回，不应要求用户重新下载。**

完整父目录 `datas of importance` 实际包含四部分：

| 目录 | 本地核对内容 |
|---|---|
| Situation Awareness Dataset | 13,548 张图像、11,968 个掩膜、AR 的 MASK-NOAA.xlsx；配对 11,914，图像无掩膜 1,634，孤立掩膜 54 |
| Standardized Solar Observation Image Dataset | 46,328 张 JPG，包含 AIA 131/193/211/304、EIT 195/304、Hα、连续谱及 HMI/MDI 磁图 |
| Solar Flare Forecasting Dataset | 4,288 份 AR 参数 TXT、4,308 份耀斑指数 NPY、C/M/X 三组各 4,308 份标签 NPY，以及 flare list.xlsx |
| Code | AIA、连续谱、Hα、磁图四份预处理 Python 源码；仅查看，不自动执行 |

参数文件实际有 `Num, NOAA_AR, MGB_PIL, R, MGB, Total_Unsigned_Flux, Area, Hale, McIntosh` 字段；事件表实际有日期、起止/峰值时间、CLASS 与 NOAA_NUM。预测数据已经存在，后续工作是解析和验证关联，不是寻找未下载的数据。这里的 13,548 仅是结构分割子集的图像数量；标准化观测图像尚未全部接入当前网页，两部分可能存在重复内容，不应直接相加当作独立样本。

父目录核对报告保存在 `out/acceptance/full-source-inventory.json`。事件表实际非空数据行 23,566；指数与 C/M/X 三组标签均分别与 4,308 份 AR 掩膜同名匹配。此核对证明预测产品实际在本地，尚不等同于对官网原压缩包进行逐文件校验和认证。

新增语义抽查：每类按排序间隔抽 30 份掩膜，AR 含 `0,1,2,...` 的多个实例编号；CH、FL 各 30 份均仅 `0/1`，应首先解释为类别前景。CH 的 30 份中有 29 份前景不连通，FL 同样为 29/30；这些不连通区域不能因为值都为 1 就称为一个科学实例。AR 抽样的 150 个非零编号中，31 个编号具有多个不连通分量，不能简单用连通域替换原始实例。本结论来自抽样，阶段 A 会逐文件审计后确定完整标签语义。

此前平台把所有非零值统一解释为实例，CH/FL 的统计与展示需要随此审计修正；图像索引数量不因此变化。CH/FL 语义掩膜保留原状，连通域生成的编号属于派生候选，不能伪称原始实例真值。AR 的 NOAA 关联保留，模型预测不能仅凭新实例编号自动赋予 NOAA 编号。

本机 `nvidia-smi` 实测 RTX 5060，显存 8,151 MiB；CPU Ryzen 5 5600XT，6 核 12 线程，内存约 32 GB。现有 mdva 环境 Python 3.10.20，未安装 torch。算法页 `has_gpu=False` 是旧代码固定返回，不能当成硬件事实。

## 三、候选模型与取舍

| 角色 | 首选 | 为什么适合 | 必须明确的限制 |
|---|---|---|---|
| 人工点选/框选辅助 | SAM 2.1 Tiny，必要时 Small | 官方支持图像提示与掩膜生成，可先不训练即验证交互 | 不自动识别太阳类别，置信分数也不是已校准的类别概率；太阳弱边界需实测 |
| CH 冕洞自动分割 | U-Net + ResNet18 | 直接学习二值栅格，适配现有标签；轻量起步 | 需要领域训练；不宣称识别了每个物理实例 |
| FL 暗条自动分割 | U-Net + ResNet18 | 保留细长结构、孔洞和二值像素监督 | 与 CH 分开训练；不同台站图像的迁移需独立测试 |
| AR 活动区实例分割 | Mask R-CNN ResNet50-FPN | 直接接受每实例二值掩膜，允许同一实例不连通 | 比 U-Net 重；先在 8 GB 上验证，ROI 分辨率对细节有影响 |
| 前景基线 | 同架构 U-Net | 统一像素指标，识别是否真正优于简单方案 | AR 二值并集丢失实例身份，仅用作对照 |
| 检测/定位 | 由分割结果派生框 | 避免重复训练与矛盾结果 | 必须标记为派生框 |

依据：[SAM 2 官方仓库](https://github.com/facebookresearch/sam2)、[SMP 官方实现](https://github.com/qubvel-org/segmentation_models.pytorch)、[torchvision Mask R-CNN 接口](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.detection.maskrcnn_resnet50_fpn.html)。上述框架的自然图像预训练权重只作为初始化，不是现成的太阳识别器。

YOLO11/YOLO26 分割列为后续速度对照，不作为首轮统一答案。其[实例标签格式](https://docs.ultralytics.com/datasets/segment/)以多边形为主，而本地 CH/FL 为二值前景、AR 还存在同编号多分量；直接转换会引入额外标签假设与近似。已有 YOLO 导出能力不能证明 YOLO 训练监督完全等价于原始像素标签。

GroundingDINO、YOLO-World、T-Rex2 不列为首轮默认：没有证据证明通用开放词汇权重可以可靠区分这些观测中的太阳结构。[SAM 3](https://github.com/facebookresearch/sam3) 保留候选位置，但未在本机验证其资源需求与太阳任务效果，不因为更新就取代较小的提示分割基线。

原团队的 [SPNet/FPNet 研究](https://arxiv.org/html/2508.06892v1) 是领域参考。若找到明确授权、可下载且适配输入的官方权重，可以优先做外部对照；本轮没有核验到可直接交付的权重包，不能以“已有同名论文”承诺即插即用。若其训练集覆盖 SSAFD，评测必须标记重叠风险。

## 四、实施阶段及交付门槛

### A. 完整数据登记、标签语义和评测集

1. 登记父目录下结构标注、标准化观测、耀斑预测三个数据产品与代码说明，保持原始源只读。当前网页仅接入结构标注子集，需要新增完整目录的索引、分组浏览与关联，不把“未接入”叫作“未下载”。逐文件记录 dtype、取值、空掩膜、形状、损坏、每编号分量与孔洞；修正原始语义/实例类型。审计是读取，写入独立报告，不修改源文件。
2. 解析观测日期、仪器、波段与台站。FL 文件名格式不统一，不能仅用一条日期正则；无法识别的进入待处理清单。
3. 建立标签来源：原始参考、人工复核、模型预测、派生连通域；有无掩膜和“审核状态”分开。现有原始掩膜不会因为 annotation 表为空而被误当无标签。
4. 未配对的 1,634 张图像不作为全背景训练样本；54 个孤立掩膜不进入训练。采样必须覆盖不同年份、仪器和难例。
5. 优先按共同日期块划分训练/验证/测试，并对 AR 按 NOAA 活动区检查跨集合重叠；跨边界的同源/重复/派生样本整体处理或剔除。可先考察训练至 2020、验证 2021–2022、测试 2023–2024，但必须先确认各类别覆盖，不能为缺少该年份的台站生成虚假测试结果。
6. 对未知 NOAA 的 CH/FL 使用时间块、近重复和相邻日观测隔离，边界保留隔离带。耀斑预测若后续加入，需额外清除 24 小时目标窗重叠。
7. 先人工核查每类 100 个测试样本形成冻结评测集，不把此前用于反复工程调试的 90 对样本直接称为独立模型测试集。测试集不参与伪标签训练、主动学习、阈值选择或模型选择。

交付：标签语义报告、样本元数据、固定 split 清单及哈希、训练可用数/排除原因、来源与许可记录。

### B. 模型运行环境和任务底座

1. 保留现有 mdva 环境，新增独立模型环境，例如 Python 3.11 的 `mdva-ai`；不把所有深度依赖塞进启动器和 HTTP 进程。
2. 使用支持 Blackwell 的 PyTorch/CUDA 运行包，锁定经本机验证的 torch/torchvision 组合。官方 [PyTorch 2.7 发布说明](https://pytorch.org/blog/pytorch-2-7/)已介绍 Blackwell/CUDA 12.8 支持，但最终选择以 Windows 当前官方安装矩阵及真实运算为准；`nvidia-smi` 显示的 CUDA 13.5 不是“本机已安装全部模型依赖”的证明。
3. 验证 CUDA 可见、设备架构、卷积/注意力、实际模型前向和峰值显存，而非只测 import。Windows 首选原生可维护安装；SAM 官方建议 WSL，若遇扩展构建问题，先试官方允许的无可选 CUDA 后处理方式，仍不稳定再评估 WSL，不默认要求用户迁移桌面环境。
4. GPU worker 常驻，单队列并发 1、默认 batch 1；按需加载模型，切换时卸载，设置缓存上限。训练和在线推理争用显存时暂停训练或明确拒绝任务。
5. 现有 `annotate/prompts.py` 每图创建 backend，并按 CPU 核数开启多个线程/进程，不适合 GPU，必须单独分流。网页进程保留任务与 SQLite 写入责任，worker 仅返回受控目录下的掩膜、元数据与错误。
6. 安装/导入模型是显式动作。推理运行不自动下载权重、不访问云端。模型包有来源、版本、哈希、许可和预处理配置；加载格式与来源需验证，不能任意反序列化未知 Python 对象。

交付：本机环境锁定文件、显卡能力修正、模型目录与能力清单、持久化任务队列、逐项成功/失败/取消/重试状态；普通网页不依赖模型环境才能启动。

### C. 先交付可用的交互辅助

1. 安装本地 SAM 2.1 Tiny，Small 作为同批对照，不一次装所有大权重。
2. 画布提供正点、负点、框选，显示候选掩膜和多个候选之间的切换；类别由当前任务或用户指定。
3. 当前图像 embedding 缓存，连续加点只更新掩膜；缓存键包含图像指纹、预处理与模型版本。支持撤销提示和切换原图对照。
4. 预览默认不入正式标注；明确接受后保存机器候选来源，不覆盖人工标注。将模型栅格转成多边形时明确近似，保留原模型栅格用于追溯。
5. 不把每日太阳观测当作连续视频直接传播。跨日传播涉及太阳自转、时间间隔和结构生灭，放到专项评估后再开放。

交付：无需等待领域训练即可使用的点选/框选辅助；AR/CH/FL 各类难例报告、首次编码和热交互耗时、峰值显存。

### D. 训练领域模型并开放整图/批量自动标注

1. 先跑传统阈值/形态学及 U-Net 前景基线，所有指标逐类报告。训练直接读原始 NPY，不读多边形近似导出。
2. CH、FL 独立 U-Net，起步 ResNet18；二值 BCE + Dice，FL 加入边界/细长结构评估。先做 512 输入、batch 1–2 与混合精度试验，再按真实显存提升批量/分辨率。
3. AR 用原始编号生成逐实例二值 mask 训练 Mask R-CNN；保留同编号多分量，类别为 AR，NOAA 是关联元数据，不是分类标签。原始编号不作为跨图永久 ID。
4. AR 尝试全图缩放到 512 的可行性和实例召回，再验证较高分辨率；不能为省显存直接切碎活动区而丢失实例关系。FL 若用重叠切片，要定义边界拼接和原坐标还原。
5. 数据归一化依据仪器/图像类型固定。当前 JPG 训练不把显示拉伸随意变化作为新物理观测；mask 仅用最近邻变换。不要在磁图 JPG 上随机反相后声称保留了磁极物理意义。
6. 超参数搜索只使用验证集；每模型先做小训练可行性试验，再做固定预算正式训练。记录 checkpoint、seed、数据版本、预处理与环境。
7. 批量模型先对 1,634 张无掩膜样本生成独立候选版本；有原始标注的样本允许模型对照，不覆盖参考。审阅阶段逐条/批量接受、拒绝或修改，初期关闭自动批准。

交付：AR 实例模型、CH/FL 语义模型、各自模型卡与真实指标、完整批量工作流及可重跑结果。

### E. 人工反馈与主动学习

把低置信、模型分歧、异常面积、太阳边缘和跨台站失效样本优先推入审核队列。置信分数在验证集校准，不把 SAM mask-quality 分数和分类置信度混用。人工确认的数据才进入下一轮领域训练，预测与人工修订版本分别保存；冻结测试集始终排除。

交付：难例队列、人工修订来源记录、可控重训入口及模型回滚；重训属于显式任务，不在浏览时偷偷执行。

## 五、平台与接口改动

- `backends/base.py`：新增真实分割任务、运行设备/输入条件/输出类型；不直接改名把 deep_stub 变成真实实现。记录模型是否已装、权重是否可用与当前数据是否兼容。
- `backends/probe.py`：真实 GPU/显存和模型环境自检；移除固定无 GPU 的假设。
- 模型 worker：以本机进程通信接收任务，不新开远程服务。模型常驻与任务调度独立于传统 CPU 后端。
- 标注存储：补充语义/实例 mask artifact 与版本，记录 source_kind、model_id/hash、prediction_id、输入版本、预处理和坐标变换。现有 `Ann` 没有栅格类型，不能只用 `list[Ann]` 把全部模型结果压成单轮廓。
- 展示：模型结果、专家参考、当前人工标注三层可独立开关；人工接受和审核分开，原始参考的有无和审核状态分开。
- 导出：明确原始参考、模型候选、当前审核结果。CH/FL 支持语义 PNG/NPY，AR 支持实例 COCO RLE；模型/人工栅格使用真实来源，不能通过 existing original 开关伪装为源真值。多边形编辑后的当前结果以该版本为准，不能悄悄导出编辑前的模型 mask。
- 建议增量接口：模型列表/自检、预测任务创建、任务结果、接受/拒绝、取消/重试；可沿用现有 `/api/tasks` 和预标注入口的兼容外观。所有路径由数据源 ID、相对 URI、受控 artifact ID 解析。

## 六、其他工作类型

第一轮需要分割，不必为了展示多模型而增加一个用途重复的检测器。质量检查先沿用传统算子；可补充前景面积、离盘位置、连通域数量、预测与参考差异等规则。待人工质量标签积累后再评估轻量质量分类器。

耀斑预测所需的物理参数、耀斑指数、C/M/X 标签和事件表实际已在 `Solar Flare Forecasting Dataset` 内，标准化观测在另一个同级目录。应建立“观测日期/时刻 + NOAA + 原始 AR 实例”的关联：按区域读取标签，区分背景与未发生事件，并核验未来 24 小时窗口定义。参数表 4,288 份与 AR 掩膜 4,308 份存在覆盖差异，须报告并查明，不据此推断下载缺失。事件表样例 NOAA_NUM=1067、参数表 NOAA_AR=11067，需核对编号缩写规则及日期，不能盲目固定加 10000。

关联验证后即可用现成表格参数训练逻辑回归和梯度提升树基线，再考虑融合磁图/AIA304 或时序模型；报告 TSS/HSS、PR-AUC、Brier、可靠性曲线与事件级分割，不能只报准确率。物理量使用已提供参数表，不能从 8 位 JPG 反推磁通量。原始 FITS 在本次完整父目录后缀清单中仍未发现，但这不妨碍使用官方预计算物理参数。

## 七、验收与资源预算

| 层次 | 必验项 |
|---|---|
| 数据正确性 | CH/FL 二值语义与 AR 实例区分；参考不改写；无标签不充当负样本；同源/时间泄漏检查 |
| 分割质量 | CH/FL Dice、IoU、边界指标及空图误报；AR 前景指标 + 实例 AP/召回、合并/拆分错误；按年份/台站/尺寸分组 |
| 交互效益 | 同批样本的纯手工和模型辅助标注耗时、修订次数及最终质量；不是仅展示几张成功图 |
| 工程 | 冷/热推理、P50/P95、峰值显存、失败恢复、停止等待与真实取消、断网模型推理 |
| 生命周期 | 权重哈希、模型与数据版本、结果重启读取、导出回读、模型升级/回滚与基础网页独立可用 |

初始工程目标：热态单目标提示反馈争取 1 秒内，单图自动分割争取 2 秒内，模型进程峰值显存争取控制在约 6 GB 内，为桌面保留余量。以上是实测前的优化目标，不是已达到的性能。标注效率争取较纯手工节省 30%，最终质量不得劣于人工基线；达不到则只保留辅助模式或继续迭代。不能预先承诺统一 90% 准确率，更不能仅凭分数自动批准候选。

先以每类少量训练数据和 100 张推理试验测算完整训练时间，再制定 GPU 小时预算，不直接承诺整轮训练耗时。安排单模型常驻、batch 1、混合精度，训练与在线推理错峰。CPU 回退应明确标记，不能静默回退后仍显示 GPU 性能。

## 八、执行顺序

A 完整数据索引、关联、语义与冻结评测 → B 环境与 GPU worker → C SAM 交互辅助 → D 领域训练与批量预标注 → E 人工反馈迭代。耀斑参数与标签解析可在 A 阶段准备，在自动标注主线交付后独立实现预测基线，不再等待重新下载。每阶段完成可演示的局部交付，不要求先复刻整个原团队 AI 预报员。

首次实际实施优先完成：修正 CH/FL 标签解释、确认 GPU 栈、跑通一张图 SAM 提示与保存，然后再扩大为批量训练。此前交接中的深度禁用注释、固定显卡状态与演示实测都须按当前用户目标更新，不能继续作为“不接模型”的依据。
