# CNN193作者权重与多通道配对核验（2026-11-16）

本轮取得了作者公开浏览器演示所引用的CNN193权重，完成了原运行时与本地转换的数值核验，但没有找到可以直接替换现有CH模型的方案。原AR/CH应用模型及其独立测试成绩保持原样。本轮没有训练、没有重新打开原测试集或校准集。

## 1. 公开权重已经找到，不能再说完全没有公开模型

[原作者CNN193仓库](https://github.com/observethesun/coronal_holes#demo)链接了[浏览器演示](https://illarionovea.github.io/)，该演示使用[公开Keras模型及分片](https://github.com/illarionovEA/tfjs/tree/a73a848bbc7eb5ef012daa9373a83fd7ee8cfd9a/keras)。

- 权重提交：`a73a848bbc7eb5ef012daa9373a83fd7ee8cfd9a`，提交记录日期2018-08-11。
- 25个分片、46个张量、6,177,505个float32参数值。结构JSON和全部分片的字节数、Git blob和SHA256均已核验。
- 原生输入为256×256单通道；原浏览器使用彩色图的红通道，而不是Pillow灰度亮度通道。
- 原生输出层为线性激活。原演示用`Math.round(value)===1`绘制区域，等价于`floor(value+0.5)==1`，不能悄悄加sigmoid或寻找新阈值，然后称为原演示结果。
- 该2018年公开演示权重不是SSAFD数据团队的SPNet权重，也没有充分训练履历可供验证。尚未独立核实权重再分发许可，目前仅用于本地研究评价。

## 2. 转换正确性已经单独核验

模型按白名单图层读取普通JSON和float32数组，不执行pickle或Keras自定义代码。卷积HWIO、转置卷积HWOI分别转换为PyTorch参数排列；转置卷积保留TensorFlow SAME的末行、末列裁切规则。Dropout在推理时关闭，输出保持线性。

原演示bundle只在隔离的本地Chromium页面中加载其TensorFlow.js库，没有启动演示应用。所有外部请求被拦截；图像和权重均从本地传入，没有上传用户数据。

核验使用零值、固定随机32×32输入的中间层及最终输出，以及一张完整CH验证图的原生256×256输出。绝对/相对容差均为`2e-5`；最大绝对差异`5.72e-6`，最终二值输出无差异。GPU对同一真实输入的最大绝对差异为`2.86e-6`，二值输出无差异。这是有限输入上的数值一致性证据，不是所有输入逐位一致的证明。

输入严格沿用原演示：Chromium解码图像，绘制到1024×1024画布，取红通道、float32除以255、旧版非半像素坐标的双线性缩放到256。整数四倍缩小时等价于取画布坐标`(4y,4x)`；首张缓存与原TensorFlow.js预处理逐像素相同。没有以现代半像素插值或Pillow灰度转换替代。

证据在`out/solar-model-sources/cnn193-browser-20261116/numerical-parity.json`、`keras/snapshot.json`、`parity-01`及`parity-02`。数值核验不会自动证明科学准确性、训练来源、许可或部署条件。

## 4. 作者示例非空，支持输入域差异方向，尚未定位全部原因

另从演示源码同一版本取得其4张示例，固定[演示仓库提交](https://github.com/illarionovEA/illarionovEA.github.io/tree/6932a61dd3d5d83530aa2c21cf2c482f5b39e38b)，核验Git blob后使用相同浏览器预处理和权重。4张均得到非空区域，原生256网格前景像素分别为1299、2859、2037、1895。示例没有对应参考掩膜，不能据此报告准确率或Dice。

![作者固定首张示例输入与非空输出](F:/毕业设计多图像浏览器/MulimgViewer-master/out/recognition-improvement-20261116/author-browser-01/review/author-demo-fixed-first.png)

本地数据是标准化灰度、白色日面外背景，示例是黑色背景的SDO彩色浏览图。数据团队提供的AIA处理代码还包含截断、平方根映射、翻转、日面尺度统一等操作，但不能证明每个已下载JPG都由同一脚本版本生成。

现有证据支持输入域不匹配的判断方向，未隔离背景、亮度映射、裁切、方向和历史训练来源各自的作用；不能把原因全部归于背景，也不能说“转灰度”“换黑底”就已经适配成功。

决定：不登记、不部署这套权重到当前输入；不修改现有模型包。若继续，只能提交有限的训练样本输入域对照或取得可核验的原始观测映射，不能在原测试集上试映射、挑阈值。

## 5. 多通道不能按同一天直接拼接

对冻结CH训练/验证清单与已下载标准观测目录做了全量文件名时刻审计：193通道5048张、211通道5071张、共同名义时刻5023个；没有重复名义时刻或无法解析的JPG文件名。没有读取测试图像或参考掩膜。

| 与CH标注图时刻对应 | 训练2410张 | 验证526张 |
|---|---:|---:|
| 193、211均精确同名时刻 | 34 | 0 |
| 最近共同通道时差≤30分钟 | 34 | 0 |
| 最近共同通道时差≤1小时 | 203 | 7 |
| 最近共同通道时差≤3小时 | 790 | 81 |
| 绝对时差中位数 | 5小时 | 5小时 |
| 最近共同通道处于目标之后 | 546 | 16 |

例如，2019-01-28的CH标注图为06:00，对应标准观测目录最近共同通道为00:00，相差6小时。相邻时刻可用于有时差说明的浏览，不能当作未经配准的同一像素输入；未来资料也不能当作早先时刻已知的预测输入。

时刻来自文件名，暂按UTC解释，尚无FITS头时间和WCS配准验证。相同文件名也不等于相同像素或处理方式。**这是已下载产品的采样、处理方式差异，不是用户没有下载完整。** 现阶段不启动基于这些日图直接拼接的多通道训练。

证据为`out/recognition-improvement-20261116/channel-pairing-01/{summary,pairs,inventory}.json`。本地太阳目录当前已有93,366条产品记录、59,876个图像文件、10,260个日期及23,566条事件；旧资料里“跨产品目录为0”的描述已过时，本轮没有重复索引或下载原始数据集。实时目录返回保存在`current-catalog.json`。

## 7. 接续

本轮原始证据目录不可覆盖；新方案使用新编号。

1. 现有AR/CH识别、机器掩膜及COCO下载仍可使用，适用范围保持原模型卡；FL、独立空间天气预测仍未交付。
2. 作者权重路径已经打通，下一步仅对有明确来源依据的输入映射做训练样本小范围控制实验；先锁定对照、门槛、预算，再决定是否评价验证集。
3. 多通道路线先解决标签时刻对应、原始观测产品及几何配准，不扩充当前日图拼接训练。
4. 预测路线继续核验五个物理参数的定义、单位与实时可获得性，不能用JPG灰度或分割面积冒充磁通等物理量。
5. 保留当前质量未达标的事实，不因取得作者权重而宣称模型升级，也不恢复旧训练队列。
