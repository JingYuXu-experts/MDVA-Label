# 太阳活动观测：交互修复与使用说明

## 原因与修复

原通道选择仅更新v-model，没有请求触发器；画面标题却取自下拉框，造成“文字换了、图没换”。本机修复前太阳归档缓存只有304通道。修复前源码和审计在`out/acceptance/solar-observation-20261112/`。

现改为切换通道自动读取，画面标题、原始链接和观测时间均取自真正载入且完成解码的影像。新通道载入前清空旧通道画面，失败明确报错，可重试。快速切换会中止旧等待并检查响应代次；旧响应不能覆盖新选择。返回三维后再打开观测页，保留原通道和回放位置；后台默认304请求也不能覆盖用户选择的纹理。

元数据和图片首次下载可能合计超过旧前端30秒超时；现按单帧60秒等待上限显示真实等待秒数，可停止等待。已发出的服务端获取可能继续完成缓存，不宣传为取消下载。首帧先显示，其余时序最多两个并发请求；失败、重复影像分别提示，不把同一张图充成视频。

后端新增`/api/sw/solar/image?channel=...&latest=true`，保留原按UTC时间查询接口。近期查询返回上游最接近当前的可用实测图，明确实际延迟；历史查询仍拒绝偏差超过30分钟的匹配。该规则对缓存同样执行。缓存元数据不能替代图片文件存在性检查，过期文件按同一不可变图像ID重新取回；离线近期查询只使用实际仍可读取的本通道缓存。

## 应该怎样使用

1. **查看近期观测**：选择304、171、193、HMI或LASCO通道后自动载入。勾选每分钟检查新图，更新不会积累成未经用户请求的时序。不是连续直播，画面标注UTC观测时间、距今多久和上游延迟；超过30分钟以警示文字显示。
2. **历史回放**：修改UTC回放起点自动读取单图；选采样间隔，再点击“载入时序（最多13帧）”。取得至少两张不同观测后可播放、上一帧、下一帧、拖动时间轴。修改采样间隔可重新载入已有时序。历史模式不被当前资料自动覆盖。
3. **2012日珥喷发案例**：载入2012-08-31真实304观测时序，明确标记历史教学案例，不冒充今天。
4. **看局部**：滚轮或滑条放大后拖动，恢复完整视野。放大是看细节的操作，不是模型推理。
5. **离线保存**：固定成功载入的时序，缓存清理保留这些图像；没有缓存的时间和通道不能在断网后凭空生成。

通道菜单表示观测仪器/波段及适合观察的结构；尚未叠加训练模型结果。AIA304、171、193、HMI磁图和LASCO对应独立数据源，见[Helioviewer通道表](https://api.helioviewer.org/docs/v2/appendix/data_sources.html)。影像查询和不可变ID下载依据[官方API](https://api.helioviewer.org/docs/v2/api/index.html)。

## 实测与验收

六个真实通道均成功下载，图像ID、文件SHA256不同，解码尺寸1536或1024像素。首次请求本次约4.9—11.3秒；已有图像后的浏览器切换约0.3—2.0秒。耗时会随上游网络变化，不能作为固定服务承诺。

本次取样时AIA落后约22—28分钟，HMI约158—161分钟，LASCO约33小时。页面如实显示延迟，不把“最新可用”写成“此刻太阳”；将来更新以实际记录为准。

- 后端观测、监测、磁层关联回归34项通过，含六个独立sourceId、近期延迟、历史门槛、未来影像拒绝、缓存文件恢复与断网通道隔离。
- Chromium隔离数据验证自动切换、标题与图像一致、快速切换竞态、近期刷新不积累、历史不刷新、日期切换、时序播放与单步、离线固定、案例历史标签、失败重试、重复图不虚构视频、停止等待及390px布局。
- Chromium正式页面逐一读取六个真实通道，确认图片均完成解码且资源ID各不相同；全屏与手机无横向溢出，无JavaScript异常。
- 前端类型检查、lint、生产构建通过；保留原图表/三维大块的500kB构建提示。
- 验收采用软件WebGL，不占用训练GPU；只重启网页服务，训练进程继续。未修改活动模型的数值源码及冻结数据。
